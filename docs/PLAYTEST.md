# 测试与平衡记录

## 1. 自动化

```bash
npm test          # 24 项引擎单测（node:test）
npm run validate  # 内容校验：id / goto / 条件 / 物品 / 敌人 / 成就引用
npm run simulate  # 12 个种子的完整人生模拟
npm run test:ui   # Playwright 端到端 19 项（需先 npm run serve）
```

### 1.1 引擎单测（24 项）

覆盖：表达式优先级与字符串/数字比较、灵根权重、种子可复现、开局初始化、修炼推进时间、冲关升层、突破概率、存读档往返、事件分支、战斗击杀、天劫成功/失败、寿终/魔化结局、成就解锁幂等、宗门晋升、结局表完整性、成就 id 唯一、事件注册表唯一。

其中两个回归用例来自真实 bug：

- `char.sectId === "qingyun"` 曾对所有角色返回 true（`num('taixuan') === num('qingyun') === 0`）。修复：仅当两侧都可数值化时才按数字比较。
- `openEvent` / `act_breakthrough` 曾缺失，导致历练与冲关点击后无响应。现在有专门用例覆盖。

### 1.2 内容校验

`tests/validate.mjs` 扫描全部节点：

- id 唯一
- 每个 `goto` 都有目标节点
- `ending` 在结局表里
- `items` / `removeItems` / `cost.item` 在物品表里
- `combat.enemy` 在敌人表里
- `achievements` 在成就表里
- 所有 `require` / `roll.expr` / 成就 `check` / 结局 `condition` 能被表达式解析器编译
- 每个选项至少有一个结果（outcome / roll / combat / action）

当前：**errors 0 / warnings 0**。

### 1.3 端到端（Playwright，19 项）

流程：标题 → 建角（出身、性别、姓名）→ 抽灵根（等待动画结束）→ 接受 → 主界面 → 点行动 → 继续 → 数字键选择 → 存档到槽 1 → 刷新 → 继续 → 读档 → 事件分支（古井神识检定）→ 结局 → 轮回 → 图鉴（隐藏成就遮蔽）→ 控制台零错误。

截图产物在 `tests/artifacts/`（已 gitignore）。

## 2. 平衡模拟

`tests/simulate.mjs` 使用一个「稳健型」策略：能突破就突破、没宗门先找宗门、心魔高就沉淀、其余时间在修炼/历练/宗门事务/坊市之间轮换；战斗优先普攻，血低于 30% 服丹或遁走。

10 个种子（seed = 1000 + i × 7919）的结果：

| 指标 | 均值 |
| --- | --- |
| 单世选择次数 | ~650 |
| 单世年数 | 116–137 年 |
| 遭遇的不同事件 | 55–63 |
| 解锁成就 | 27–33（单世内） |
| 最高境界 | 渡劫（realm 8） |
| 结局分布 | 飞升 8 / 天劫身死 0（8 局样本） |

按每次选择 35–50 秒（读文本 + 权衡 + 看结果），单世约 **7–9 小时**。

### 关键数值锚点

| 参数 | 值 | 位置 |
| --- | --- | --- |
| 打坐 | 6 个月 | `narrative.js` hub |
| 闭关 | 24 个月 | 同上 |
| 历练 / 宗门事务 / 沉淀 | 3 个月 | 同上 |
| 云游 | 6 个月 | 同上 |
| 天劫每重基础成功率 | `0.9 - realm×0.022 + 道心×0.0022 - 心魔×0.002` | `game.js` |
| 天劫失败 | 气血 -45%、伤势 +2、寿元 -10 年；气血归零才死 | 同上 |
| 筑基寿元 | 260 年（随境界递增至 30000 年） | `realms.js` |
| 灵根权重总和 | 95.74 | `roots.js` |

### 调参建议

- 觉得太快：降低 `realms.js` 的 `monthly`，或提高 `state.js` 的 `needExp` 增长系数。
- 觉得太慢：提高 `monthlyExp` 里的根骨/悟性系数。
- 天劫太狠：提高基础 0.9，或把失败惩罚从 45% 降到 30%。
- 事件重复：提高 `weight` 差异、增加 `once`、给高 tier 事件加 `minRealm`。
